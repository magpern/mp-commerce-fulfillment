Commerce Fulfillment User Manual

Product: MP Commerce Fulfillment (plugin name in WordPress: Commerce Fulfillment)
Manual version: matches plugin v1.0.0

v1.0.0 WordPress / WooCommerce Warehouse operations
Important This manual describes the released v1.0.0 plugin. It does not claim that the plugin is deployed on your live storefront production site. Production cutover is a separate operational decision.

1. Introduction

What Commerce Fulfillment does

After a customer pays in WooCommerce, your warehouse still needs to pick items, pack them, capture evidence if required, print documents, ship packages, and keep an audit trail. Commerce Fulfillment owns that warehouse work:

  • Creates a fulfillment when an order becomes paid / processing (intake).
  • Guides operators through picking, packing, shipping, and completion.
  • Stores documents, package photos, shipment tracking, and events.
  • Supports barcode Scan Mode and multi-order Wave picking.
  • Provides operational analytics and health checks for leads and administrators.

What it does not do

  • It does not replace WooCommerce checkout, products, customers, or payments.
  • It does not manage inventory receiving, purchase orders, stock ledgers, or bin locations (that is a separate inventory system).
  • It does not automatically change WooCommerce stock levels when you pick or pack.
  • It does not integrate with every carrier’s label API — you enter tracking and use your carrier tools as configured.

Terminology at a glance

OrderThe WooCommerce order (source of truth for payment and line items).
FulfillmentWarehouse work for that order inside Commerce Fulfillment.

3. Getting started

Where it appears

In wp-admin, open the left menu item Fulfillment (archive icon). The top bar of each Fulfillment screen shows Commerce Fulfillment — Warehouse fulfillment workspace.

Main navigation

  • Dashboard — attention metrics and today’s counts
  • Queue — work list (open fulfillments)
  • Orders — “where is my order?” overview across store status and fulfillment
  • Documents — history of stored documents (if you can print documents)
  • Analytics — operational reports (Lead / Admin)
  • Settings — branding, photos, notifications (Lead / Admin)

The Packing Workspace and Wave Workspace open from Queue (or similar deep links). They are not separate top-level menu items.

Operational overview
Paid order→ Queue→ Pick→ Pack→ Ship→ Notify

4. Dashboard

Menu: Fulfillment → Dashboard.

The Dashboard helps leads and operators see pressure points at a glance. Typical sections include:

  • Needs attention — exception or blocked work
  • Oldest open — aging fulfillments
  • Unassigned — work without an assignee
  • Today — open count, exceptions, packed today, shipped today
Tip Use the Dashboard to choose what to work next, then open Queue to claim a specific fulfillment.

5. Queue

Menu: Fulfillment → Queue (page title: Fulfillment Queue).

The Queue lists fulfillments that need warehouse work. From here you typically:

  • Find an order by search / filters (as shown on the page).
  • Open a fulfillment into the Packing Workspace.
  • Select several fulfillments and choose Create wave from selection for batch picking.
  • Use bulk document actions such as Print picking lists (max 25)… when available.
Important The Queue shows fulfillment work. A WooCommerce order that is not yet eligible for intake (for example unpaid) will not appear as warehouse work until intake creates a fulfillment.

6. Orders overview

Menu: Fulfillment → Orders.

This screen is a read-only “Where is my order?” overview. It combines:

  • WooCommerce / store order status (payment and store lifecycle), and
  • Commerce Fulfillment state when a fulfillment exists.

It does not create fulfillments and does not change store or warehouse state. Use it for customer-service questions and to jump toward the right workspace when a fulfillment already exists.

Tip Processing in WooCommerce is not the same as Picking in Commerce Fulfillment. Always check the fulfillment state for warehouse progress.

7. Packing Workspace

Opened from Queue (and related links). Browser title: Packing Workspace.

This is the primary screen for a single fulfillment. Typical areas:

  • Order / customer snapshot and current state
  • Line items with picked / packed quantities
  • Primary action (advance to the next allowed stage)
  • Shipments, packages, documents, photos, notes
  • Scan Mode controls when you are picking or packing

Lifecycle (standard path)

Queued→ Picking→ Picked→ Packing→ Packed→ Shipped→ Delivered→ Completed

You may also move work to Problem, Waiting, or Backordered (reason required), or Cancel if you have permission.

Stale / version conflicts

If two people update the same fulfillment, or a screen is left open too long, the plugin may reject a save with a version conflict message (for example asking you to reload). Reload the Workspace and retry so you do not overwrite newer work.

Warning Do not keep multiple browser tabs open on the same fulfillment during busy shipping — it increases conflict risk.

8. Picking

  1. Open a queued fulfillment in the Packing Workspace.
  2. Advance to Picking (primary action).
  3. Increase picked quantities on each line until they match ordered quantities (checklist controls or Scan Mode).
  4. When all lines are fully picked, advance to Picked, then to Packing when ready.

You cannot mark a fulfillment Picked until every line is fully picked.

Common picking errors

  • Trying to finish picking while a line is still short.
  • Scanning a barcode that does not match any line on this fulfillment.
  • Scanning more units than ordered (over-scan is rejected).

9. Packing

  1. In Packing, set packed quantities for each line.
  2. Under Packages, choose Add package.
  3. Enter at least Weight (required to confirm the package). Length, width, and height are optional but recommended.
  4. Add carrier / tracking information on the shipment as needed.
  5. If sealed-package photos are required in Settings, capture at least one Sealed package photo before finishing.
  6. Advance to Packed when all packing guards pass.
Important The plugin requires a recorded package weight before you can mark the fulfillment Packed. Dimensions are optional for that check, but entering them improves shipping accuracy.
Tip You can create a shipment early while still packing, then fill package weight and tracking before the Packed / Shipped steps.

10. Shipping and tracking

  • Create or open the shipment on the Workspace.
  • Choose a carrier (or leave the default / Other as configured).
  • Enter a tracking number (required before shipping on the standard path).
  • Ship the shipment (Workspace ship action). The fulfillment moves to Shipped when shipping succeeds.

Later stages may include Delivered and Completed depending on your process.

Administrator only Default carrier and customer email wording are configured under Settings → Notifications.

11. Documents

Document types

Packing slipPack / include in cartonAvailable from packing onward; stored for reprint.
Wave picking listBatch pick walkPrinted from the Wave Workspace.

In Workspace

Use the Documents section and Print … actions for the documents allowed in the current stage. If none are available, the UI explains that no printable document is available in this stage.

Document history

Menu: Fulfillment → Documents — immutable outbound documents. Reprint streams the original stored file. Filters include type (picking list / packing slip), order/fulfillment, and date range. Wave picking lists are printed from Wave Workspace rather than filtered here as a wave type.

12. Package photography

Section title in Workspace: Package photos.

  • Contents — optional evidence of what went into the package.
  • Sealed package — photo of the closed parcel. This is the type that satisfies a photo requirement.

Upload via camera or file picker as provided in the UI. Preview photos from the gallery / lightbox controls.

  • Capture: Warehouse Operator and above (capture permission).
  • Delete: Warehouse Lead / Administrator / Shop Manager only. Operators cannot soft-delete photos.

When Require sealed-package photo is enabled in Settings, you cannot mark the fulfillment Packed until at least one active sealed-package photo exists. Retention (months) is configured by administrators; after retention, image files may be purged while audit metadata remains.

13. Barcode & Scan Mode

In the Packing Workspace, open the Scan Mode panel.

  • Enter Picking Scan Mode when the fulfillment is in picking.
  • Enter Packing Scan Mode when packing.
  • Use a keyboard-wedge scanner, or type a SKU and press Enter.
  • Undo last scan corrects the previous successful scan.
  • Exit Scan Mode returns to normal controls. Toggle Sound on / Sound off as needed.

Status shows Ready and a Recent scans list.

SituationWhat happens
Unknown barcodeRejected — no item on this fulfillment matches.
Over-scanRejected — item already fully picked or packed.
Wave barcode in Workspace Scan ModeRejected — wave barcodes belong in Wave Scan Mode.

14. Wave & batch picking

A wave groups several fulfillments for one combined picking walk.

  1. In Queue, select fulfillments and choose Create wave from selection.
  2. Open the Wave Workspace.
  3. Activate the wave when you start the walk.
  4. Print the wave picking list if needed.
  5. Use Enter Wave Scan Mode for FIFO pick scanning across members (pick only — not pack).
  6. Pause / Resume as needed; Complete or Abandon when finished.
Important Wave Scan Mode only covers picking. Packing, photos, shipping, and notifications remain per fulfillment in each Packing Workspace after the wave pick is done.

FIFO behavior means the system advances outstanding wave lines in order — scan the next expected item rather than packing inside the wave screen.

15. Tracking & notifications

After a shipment is shipped (or delivered), the Workspace shows notification status and a Send tracking notification button (requires shipment permission).

Strategies (configured in Settings)

Strategy labelBehaviour (conceptually)
Completed-order emailRelies on WooCommerce completed-order style customer email path as configured.
MPCF shipped emailCommerce Fulfillment sends its shipped / tracking email.
BothBoth paths may apply per configuration.
DisabledNo automatic MPCF tracking email.

Manual Send tracking notification can resend (forced) when operators need to retry after a failure. Status values you may see include sent, failed, suppressed, or none yet.

Carrier tracking links appear in customer messaging when tracking data and templates provide them.

16. Analytics

Menu: Fulfillment → Analytics (capability required). Analytics is read-only — it does not change fulfillments.

  • Overview — today (UTC live) cards; Stage Timeline (averages); Queue ageing buckets; waves today.
  • Reports — date presets and throughput table; Export throughput CSV (UTF-8).
  • Diagnostics — top failure reasons; slow fulfillments; stalled / paused waves.
Tip Timeline and queue ageing live inside Overview, not as separate top-level tabs.

If numbers look “stuck”, ask an administrator to confirm analytics rollup schedules are healthy (see Administration).

18. Administration and health

Administrator only This section is for site administrators and technical operators.

Site Health

WordPress Tools → Site Health includes an MP Commerce Fulfillment check. Results may show critical issues, warnings, or that checks passed. Prefer resolving warnings before peak shipping hours.

Doctor, validation, and repair (conceptual)

Administrators can run read-only diagnostics and bounded repairs from the server (WP-CLI). Conceptually:

  • Doctor — overall operational health (environment, schema, storage, schedules, capacity).
  • Validate — focused checks (schema, storage, schedules, consistency, and more).
  • Repair — safe, limited fixes only (for example missing schedules or storage directories). Repairs are dry-run by default until explicitly confirmed.
  • Audit verify — checks the append-only event hash chain for sample fulfillments.

See the Appendix for command names. Day-to-day warehouse staff do not need CLI access.

Scheduled jobs & storage

Background work (photo retention purge, analytics daily rollup) runs through Action Scheduler / WordPress cron. Storage lives under the site uploads area in a protected mpcf folder for photos and documents. If storage is not writable, document and photo features will fail until fixed.

20. Common workflow examples

A. Standard single order
  1. Open Queue → select the fulfillment.
  2. Workspace: start Picking → set quantities → Picked.
  3. Start Packing → pack quantities → add package → enter weight → sealed photo if required.
  4. Enter tracking → Packed → Ship.
  5. Print packing slip as needed → Send tracking notification if required.
B. Scanner-assisted order
  1. Open Workspace → Enter Picking Scan Mode.
  2. Scan each unit until lines are complete → exit Scan Mode → advance stages.
  3. In packing, Enter Packing Scan Mode and scan to confirm packed quantities.
  4. Finish package weight, photo, tracking, and ship as in example A.
C. Wave picking several orders
  1. Queue: select multiple fulfillments → Create wave from selection.
  2. Activate wave → print wave picking list → Enter Wave Scan Mode.
  3. Scan picks (FIFO) until the walk is done → Complete wave.
  4. Open each fulfillment Workspace to pack, photograph, ship, and notify individually.

21. FAQ

Does picking reduce WooCommerce stock?

No. Commerce Fulfillment does not mutate store stock as part of pick/pack.

Why can’t I delete a photo?

Operators can capture photos but only Leads / Administrators / Shop Managers can delete them.

Where is “Mission Control”?

There is no separate menu by that name in v1.0.0. Use Dashboard for operational attention metrics.

Can I pack inside a wave?

No. Waves are for batch picking. Pack and ship each fulfillment in its Packing Workspace.

Is analytics live?

Overview “today” metrics are live (UTC). Longer reports may use daily rollups maintained in the background.

Appendix: CLI commands (administrators)

Administrator only Requires WP-CLI on the server. Prefer dry-run behaviour before applying repairs.
  • wp mpcf doctor — operational diagnostics
  • wp mpcf validate <target> — focused validation
  • wp mpcf repair <target> [--yes] — bounded repair (confirm with --yes)
  • wp mpcf audit verify — audit chain verification
  • wp mpcf analytics backfill|rebuild — analytics maintenance

Full operational detail lives in the plugin’s ops documentation for site administrators.
